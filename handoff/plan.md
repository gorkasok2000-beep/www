# План исполнения: PR-2 sessionKeyTargets generation

Продолжаем после PR-1. Цель — устранить H2: повторная выдача/отзыв session key должны атомарно инвалидировать старые разрешённые получатели. Это первая правка, которая может затронуть ABI/storage, поэтому идёт отдельным пакетом.

## Scope PR-2
1. Ввести поколение ключей: у каждого signer есть `sessionKeyGeneration`, targets проверяются только для текущего поколения.
2. `registerSessionKey`: инкрементирует поколение, обнуляет spent, записывает targets нового поколения. Старые targets перестают действовать без необходимости чистить mapping.
3. `revokeSessionKey`: ключ удаляется; повторная выдача обязана использовать новое поколение.
4. Тесты: перевыпуск сужает targets; revoke+reissue не воскрешает старые targets; restricted key с self/entryPoint всё ещё блокируется PR-1 гардом.
5. Проверить влияние на ABI/web: если меняется публичный `sessionKeyTargets`, зафиксировать необходимость `export-abi` и отдельной синхронизации web.

## Ограничения
- Не трогать серверную платёжную логику в этом PR.
- Если обновление `abis.ts` требует `contracts/out`, который недоступен в среде, не генерировать ABI вручную вслепую; явно пометить шаг для пользователя.
- Комментарии и отчёт на русском.

## Workflow
