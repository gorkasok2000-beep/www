03Что сделано в PR-1 – PR-4

PR-1 · контрактный hotfix
  • Гард в _consumeSessionAllowance: ключ не может вызывать сам кошелёк и EntryPoint — закрыта эскалация через registerSessionKey / upgradeToAndCall / withdrawDepositTo
  • upgradeToAndCall запрещён при frozen — заморозку больше не обойти апгрейдом
  • AgentRegistry отклоняет повторную регистрацию одного аккаунта (AgentAlreadyRegistered)
  • +6 тестов: self-call, EntryPoint-withdraw, frozen upgrade, дубль реестра
PR-2 · поколения targets
  • sessionKeyGeneration + приватные targets по поколениям: старые списки недостижимы по построению
  • Explicit-геттер с прежним селектором — web ABI не сломан; после revoke возвращает false
  • Валидация читает storage напрямую: меньше газ, нет риска ERC-7562-несовместимости
  • +4 теста: сужение списка, revoke+reissue, гард важнее списка, геттер после revoke
PR-3 · серверный hotfix платежей
  • execute разделён на фазы до/после отправки: ошибка после submit больше не ставит FAILED — платёж остаётся SUBMITTED до сверки (B1)
  • syncTransactionLogs — best-effort вне критичного пути: сбой индексатора не перезаписывает CONFIRMED (B1)
  • readUserOperationOutcome фильтрует события по userOpHash, смотрит receipt.status, «операции нет в чеке» = неизвестно, а не успех (H3)
  • Проверка in-flight и создание платежа — в одной транзакции с writer-lock SQLite: один нонс не уйдёт дважды (H4)
  • Счёт атомарно захватывается OPEN → PAYING; finalize закрывает его, только если он всё ещё захвачен этим платежом (H5)
  • CREATED старше 5 минут гасится в FAILED и освобождает счёт — «зомби» больше не блокируют агента 409 навсегда (M5)
PR-4 · индексатор, SSRF, валидация, кран
  • Индексатор сверяет log.address с эмитентом: поддельное AgentTransaction чужого контракта не попадает на витрину (M2)
  • signerUrl: запрет credentials, localhost и приватных IP, DNS-резолв при регистрации, redirect: manual при запросе подписи (M3)
  • Отрицательный valueEth и NaN в periodSeconds/ttlSeconds — 400 вместо 500; 500-ответы без сырого error.message (M4)
  • FAUCET_ENABLED, суточный лимит крана 30 ETH на агента (FaucetGrant + writer-lock), резерв оператора 1 ETH, газ отключён вместе с краном (H6)

04Gates из roadmap

Gate 0Все blocker/high закрыты и проверены прогоном: 71 тест контрактов, adversarial-тесты падают на коде до фикса, CI на чистом клоне, сквозной тест API. Закрыт.
Gate 1Testnet-safe MVP: глубина подтверждений и реорги ✓, миграции ✓, наблюдаемость ✓, SERVER_KEY за флагом ✓, webhooks ✓, bundler fallback ✓. Код собран; осталось — прогон с 5–10 внешними командами и замер p95. Сейчас здесь.
Gate 2Аудит + legal + KMS: внешний аудит контрактов, ключи оператора в KMS/HSM, юридическая рамка custodial-элементов.
Gate 3Capped pilot: реальные пользователи с жёсткими лимитами на аккаунт и на платёж, мониторинг и runbook инцидентов.
Gate 4Production: ERC-20 только после token budgets (approve/Permit2), multichain только после координации кросс-чейн апгрейдов.
